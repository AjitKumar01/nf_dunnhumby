Basket Model v4 — Code Architecture

How the code is laid out and how a number gets from the raw baskets to a held-out likelihood, a recommendation, or a simulated store week. Companion to the model specification, which covers the mathematics and the experimental record.

1 · Layers

Six layers, each depending only on those above it. There are no cycles: every module imports downward.

  PREPROCESSING   data.py         raw parquet -> the ragged assortment index (cached)
                  features.py     price / promotion / recency lookups per slot
                  pairmask.py     which products may carry phi
                  beta_target.py  empirical per-product price response

  KERNEL          ragged.py       tensor primitives: ESP, poly_tree, quadrature grids
                                  RaggedModel: energy, log Z, pi, sampling, projections

  TRAINING        fit.py          Batcher, the step, penalties, projections, goals,
                                  checkpointing, rec_eval

  EVALUATION      evalall.py      held-out likelihood, both splits, sampled not sliced
                  distcheck.py    KL / TV / KS on the size law
                  recommend_pi.py complete-the-basket on pi
                  bench_same_trips.py   every model on the SAME trips

  APPLICATIONS    env.py          RetailEnv: reset / step / step_expected / participation
                  sim_full.py     complete markdown simulation over a whole split
                  bundle.py       greedy personalised bundles
                  wtp.py          reservation prices

  BASELINES       baselines.py    Bernoulli, DPP, LinearIndex, Batches
                  baselines2.py   NDPP, Multinomial, Shopper
                  shopper_ladder.py   shopper fitted to convergence

data.py :: build()

Reads the transaction table once and emits the ragged assortment index, cached to .npz. The cache key follows the category partition, so switching partitions cannot silently reuse a stale index.

  baskets.parquet ---> trips (user, store, day, week, split)
                  ---> lines (item, category, units) as a CSR-style pointer array
                  ---> assortment: which products each store carries
                  ---> support filter: trips with more than nmax lines, or more than R
                       from one category, are dropped and REPORTED

  V3_PARTITION=<file>   names any parquet of (item_id, cat_id); it defines the ragged row
                        structure, so it also sets C and the cache filename

The temporal split is fixed: train weeks 1–82, validation 83–90, test 91–102. Trips are stored in time order, which is why every evaluation samples rather than slices.

features.py :: Features

Covariate lookups at an arbitrary set of (product, store, day, week) pairs. gather() returns price deviation, display and mailer by sparse searchsorted; recency() returns four functions of time-since-last purchase for the same (household, sub-commodity), found with one strictly-before lookup into a sorted key array.

Recency is switched off in the fitted model (--no-rec 1). Its distribution drifts on a temporal split, and it accounted for 104% of the held-out shift in b. The code stays; the term is zeroed and frozen.

3 · The kernel — ragged.py

Everything expensive is here, and all of it is exact. Baskets have wildly different sizes, so nothing is padded to a common length — the "ragged" layout is the reason this is one file.

RaggedIndex

One batch, flattened. A slot is a (trip, product) pair the trip could have bought; a row is a (trip, category) group.

  item, item_trip, item_pos    [T]        product id, its trip, its position within its row
  row_of, row_cat, row_trip    [n_rows]   which row a slot belongs to, and that row's identity
  row_size, row_pos            [n_rows]   how many slots the row holds, and where it starts
  flat_slot, slot_deg          [n_rows]   scatter target into [B, Cpad]; degree cap per slot

Primitives

FunctionWhat it computesWhy it is written that way
esp_bucketedelementary symmetric polynomials e_0..e_R per rowthe stable e_r += w_i e_{r-1} recursion, never Newton's identities, which cancel catastrophically at R=23. Rows are bucketed to (8, 32, 96, 256) so padding wastes ~2x rather than 25x
poly_treeproduct of category polynomials, truncated at nmaxpairwise tree rather than a sequential fold: fewer, larger kernels
seg_max, seg_sumsegment reductions over tripsone scale per (trip, draw); a per-row scale would not survive the convolution
gh_grid(d,q)dense Gauss–Hermite, q^d nodes, positive weightssampling z needs a distribution, and Smolyak weights are signed
smolyak_grid(d,q)sparse grid by the combination techniquethe deterministic normaliser; 681 nodes at Kz=4, q=8

The forward pass

  b_at(items, trips, ctx)          item value: lam + taste + price + promo + season + store
    |                              price is split into a common level and an idiosyncratic
    |                              deviation, scaled separately by price_kappa
    v
  log_f_ragged  /  log_f_sparse    log f(z) for a batch of z
    |   w_j = exp(b_j - ||phi_j||^2/2 + phi_j'z)
    |   esp_bucketed  ->  e_r per (trip, category)
    |   a_c(r) = exp(-rho_c r(r-1)/2)             within-category term
    |   poly_tree     ->  A_n, the basket-size generating polynomial
    |   log f = logsumexp_n [ log A_n - rho_0(n) + n*M ]
    v
  _log_Z_quad                      sum over grid nodes: signed weights, so the sum is
                                   formed in linear space after factoring out the row max
    v
  loglik = energy(S) - log(Z-1)    plus units_loglik if --units

log_f_sparse is the same value as log_f_ragged to 2.3e-16. Only phi-carrying products depend on z, so the ESP over the rest and the convolution over untouched categories are lifted out of the node loop by sparse_prepare: 83.7x at a 20-product mask.

5 · Training — fit.py

One step

  Batcher.make(trips)         -> ix, ctx (per slot), lctx (per line), house, LI/LT/LC/LU
    |                            dlp_bar (per-trip mean price) is computed ONCE from the
    |                            assortment and carried in BOTH ctx views
    v
  m.loglik(...)               -> ll, ess, pn        pn is the size law, shared with the
    |                                               penalties below at no extra cost
    v
  loss = -ll.mean()           _data_term is kept so the ESS gate can swap it WITHOUT
    |                         discarding the penalties added after it
    + size_kl  * ( cross-entropy to the empirical size law
    |              + var_w  * (log1p Var(n) - log1p emp)^2
    |              + en_w   * per-trip (E[n] - observed)^2
    |              + rkl_w  * reverse KL, which sees a tail the cross-entropy cannot )
    |              en_w   penalises PER-TRIP error, where the failure actually is:
    |                     model E[n] has median 6.5 and max 119.5, and the worst 5% of
    |                     trips carry 73% of it.  Aggregate penalties cannot see that.
    + elast_w  * (aggregate elasticity - target)^2      pins the LEVEL of price
    + pool_prod* ridge on the bilinear PRODUCT, degree 2, not on its factors
    + beta_cal_w * standardised pull on beta's cross-product PATTERN
    v
  backward, clip, opt.step()
    v
  PROJECTIONS   lam_centre    centre lam, transfer the level to rho_0 (b unchanged)
                c_max         scale phi so max_u sum_j max(phi_j'u,0) fits the grid radius
                lam_sd_max    cap the spread of lam
                rho0_curv     floor rho_0'' so Var(n|trip) stays bounded
                phi_mask      re-apply the mask
    v
  every --eval-every:  evaluate() on a RANDOM validation sample, rec_eval on pi,
                       check_goals, save best-likelihood AND best-MRR checkpoints

Gauge fixing, applied structurally in b_at

theta, delta and xi are centred inside the forward pass, not by a penalty. lam_j + mu_j'delta_w has an exact flat direction, so the likelihood cannot decide where the per-product intercept lives — only the penalties can, and they choose badly. All three must be centred: centring only the contextual terms lets the intercept migrate into household taste instead.

The seven goals

  logZ-converged     log Z at draws vs 8x agree                (always PASS on quadrature)
  E[n]-converged     E[n] at draws vs 8x agree
  E[n]-calibrated    |E[n] - observed| <= 25% of observed
  var-calibrated     |Var(n) - observed| <= 40% of observed
  sampler-agrees     the generator's E[n] matches the analytic one
  elasticity         aggregate price elasticity within tolerance of -0.121
  data-kept          the ESS gate is not discarding trips

These are tolerance bands, not a convergence criterion. A single passing line can drift back out; what matters is whether all seven hold across several evals.

Checkpoints

Resuming a converged model: lower the rate. --fresh-sched restarts the cosine over a new horizon and resets the rate to --lr, so passing it without lowering --lr puts a converged model back at full rate. Measured on the same checkpoint with the same penalty: at 0.005 Var(n) swung 92 → 284 between consecutive evals and the likelihood fell 1.9 nats; at 0.0005 it held 91–105 across 15 evals with the likelihood improving monotonically. Roughly a tenth of the original rate is the working rule.

The swings are the model, not the estimator: the eval uses a fixed trip slice and a freshly seeded generator, so its size moments are a deterministic function of the parameters.

save_ckpt writes format=2: model, optimiser, schedule, both RNG streams, iteration, cumulative iteration, best-so-far. Atomic via temp + os.replace. Two are kept — _best.pt on likelihood and _bestmrr.pt on ranking — because they do not coincide. --fresh-sched restarts the cosine over a new horizon and resets the learning rate, since a finished run resumes at its floor.

Trips are stored in time order. Any prefix is a single week. fit.py once scored va[:128] — week 83 alone, whose worst trip had model E[n] 16.5 against 117 in a random sample. The validation array is now permuted once with a fixed seed, so a prefix is a random sample and stays identical across runs.

7 · Applications

env.py :: RetailEnv

  STATE      (store, week, the trips that occasion, prevailing log-price deviation)
             Trip occasions are REPLAYED from data: who shops, when and where is observed;
             only what they buy is simulated.
  ACTION     a log-price shift, scalar / per category / per product, added to the observed
             deviation.  This is exactly how price enters b.
  REWARD     gross margin, cost = (1 - margin0) x base price.  margin0 is DECLARED.

  step()            generates baskets by Corollary 3      -> realised composition
  step_expected()   E[margin] = sum_j pi_j E[units_j] (price - cost)
                    exact, ~100x faster, no Monte Carlo noise
  participation()   a DECLARED outside option, eta.  It cannot be estimated: three designs
                    all came out with the WRONG SIGN, because dear stores are preferred
                    stores.  eta = 0 reproduces pure replay.

sim_full.py runs the whole thing over a complete split — 16,948 trips, 109 stores, 1,941 households, all 5,455 products per assortment, units included. bundle.py builds personalised bundles greedily on pi, pinning each chosen item in by raising its b so the model re-solves for the rest. wtp.py finds the price at which pi_j halves.

8 · Conventions

ConventionWhy
One function per quantity. Nothing computes an item value except b_at.b_flat and energy once drifted apart, so E(S) and log Z scored the same product differently — free reward for the optimiser.
float64 everywhere.the ESP recursion and the poly tree run to degree 120; float32 loses the tail.
Sample, never slice.trips are in time order, so a prefix is one week.
Report the median beside the mean.E[n] fails in a concentrated tail; the mean swings 7–32 while the median holds near 6.
A broken path raises._ais and recommend.py refuse to run rather than return plausible wrong numbers.
Assumptions are printed.margin0 and eta are declared in the run header, never presented as measured.
Comments carry the measurement.every non-obvious choice cites the number that forced it, so a future reader can re-derive rather than re-discover.
